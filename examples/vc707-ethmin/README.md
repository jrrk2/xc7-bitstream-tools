# ethmin: a picorv32 SoC with gigabit Ethernet

Ported from [`vc707-openflow-demos`](https://github.com/jrrk2/vc707-openflow-demos)'s
`ethmin`. A PicoRV32 running from block RAM, a UART, a 1G Ethernet MAC with
DMA and packet buffering, and an SGMII physical layer generated by LiteEth on
a GTX transceiver.

It is here because it is the largest thing in this repository that exercises
the parts of the fabric a small example never reaches:

| | |
| --- | --- |
| cells | 5336 |
| flip-flops | 1840 (`FDRE`/`FDSE`/`FDCE`/`FDPE`) |
| `CARRY4` | 223 |
| block RAM | 18 `RAMB18E1`, 1 `RAMB36E1` |
| distributed RAM | 12 `RAM32M` |
| wide muxes | 11 `MUXF7`, 5 `MUXF8` |
| clocking | 3 `MMCME2_ADV`, 8 `BUFG` |
| transceiver | 1 `GTXE2_CHANNEL`, 1 `IBUFDS_GTE2` |

## Status: blocked, at place-and-route

It synthesises cleanly and then stops:

    ERROR: failed to find IBUFDS_GTE2 site for pad 'X394Y341/IPAD_X0Y0.PAD'

nextpnr-himbaechel cannot bind a gigabit-transceiver reference clock to its
pad, so nothing needing a GT can be placed. `examples/vc707-gtrefclk` is a
forty-line reproducer of the same bug; both are in the sweep because they
answer different questions -- that one asks whether the single binding works,
this one asks whether a design that needs it then builds. The sweep runs both
every time and says UNBLOCKED when they start getting further.

Nothing downstream of place-and-route has been exercised here yet: no
bitstream, no extraction, no equivalence proof. That is the point of keeping
it in the table rather than in a branch.

## Provenance

No source file is modified from its origin. The sources come from two
checkouts of the same lineage, and which one matters:

| files | from |
| --- | --- |
| `picorv32.v`, `simpleuart.v`, `spimemio.v` | `v7-johnson-demo/picosoc` |
| everything else | `vc707-openflow-demos` (`ethmin/`, `ethsoc/`, `ibexsoc/`) |

The PicoSoC files are taken from `v7-johnson-demo` deliberately. The copies in
`vc707-openflow-demos/picosoc` are an older revision that this SoC does not
build against -- `simpleuart` there has no `DEFAULT_DIV` parameter and
`picorv32` has neither `dbg_reg_pc` nor `progaddr_reset_i`, all three of which
`picosoc_ethmin.v` uses. That demo's own flow does not hit this because it
elaborates through an SVS/Hardcaml front end that generates specialised
modules (`simpleuart__DD217.v`); reading the same file list with plain yosys
does hit it. Taking the matching revision keeps every file byte-identical to
an upstream, which is worth more than a local patch.

`liteeth_sgmii_phy.v` is generated output, checked in so the build needs
neither LiteX nor Python; regenerate it with
`ethmin/liteeth_phy/gen_liteeth_phy.py` in the demos repository.
`progmem_ethmin.v` is the firmware image, likewise checked in so no RISC-V
toolchain is needed.

Licences travel with the files: PicoRV32 is ISC (Claire Wolf), the MAC and
framing are MIT (Alex Forencich), the clock generator and pin constraints are
Apache-2.0 (lowRISC), and the LiteEth PCS is BSD-2-Clause.

## Building it by hand

    cd examples/vc707-ethmin
    yosys -p "read_verilog -sv $(grep -v '^#' sources.f | tr '\n' ' '); \
              synth_xilinx -flatten -abc9 -arch xc7 -top vc707_ethmin; \
              write_json gold.json"

Use the yosys this repository pins (`make yosys`) -- see the note on toolchain
pinning in the top-level README.
